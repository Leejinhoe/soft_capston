# 실시간 동화 이미지·영상 생성 설계

상태: 구현 전 설계 초안. 작성일: 2026-11-01. 대상: `D:\capstone\soft_capston-main`.

## 목표와 제약

- 사용자가 고른 캐릭터의 기준 이미지를 참조해, 매 장면의 이야기·선택·행동에 맞는 이미지와 영상을 원격 생성한다. 동작 에셋을 미리 만들거나 축적하는 것은 목표가 아니다.
- 앱 이용자는 개인 PC나 Colab을 켤 필요가 없다. Flutter 앱, 외부에서 접근 가능한 FastAPI, MongoDB 및 원격 생성 서비스가 네트워크로 연결되어야 한다. 서버 배포와 무료 가용성은 아직 검증하지 않았다.
- 무료 사용을 우선하되 ZeroGPU 할당량, 공유 대기열, 서비스 중지 및 이용 조건에 따라 불가능한 요청을 명확히 표시한다. 과금 기능을 자동 활성화하지 않는다.
- 생성 모델은 캐릭터 동일성과 이동 방향을 보장하지 않는다. 영상 제공 전 별도 검증이 필요하며 실패 시 가짜 성공으로 표시하지 않는다.

## 현재 코드의 재사용 범위

1. `lib/services/db_service.dart`: 장면 미디어 작업 생성 및 상태 조회. `lib/story_page.dart`: 생성 및 재시도 화면.
2. `backend/main.py`: `POST /api/stories/{story_id}/scenes/{step_number}/media/jobs`, `GET /api/media/jobs/{job_id}`, MongoDB `media_jobs` 작업 생성·중복 방지·worker claim·heartbeat 및 GridFS 결과 저장.
3. 위 기능들이 이미 원격 생성형 영상 서비스를 제공한다는 뜻은 아니다. `hf_video_provider.py`는 현재 로컬 레이어 영상 렌더러다. `hf_space_character.py`는 망원경 상황만 다루는 선택적 실험이며, 이미지 검증 전 자동 적용은 꺼져 있다.
4. 이미지가 먼저 표시되고 영상이 후에 도착하도록 상태·저장·화면을 분리해야 한다. 현재 전체 작업 종료 시 최종 상태를 기록하므로 실제 중간 공개 경로는 구현 및 검증이 필요하다.

## 처리 흐름

1. 선택 결과로 장면 텍스트와 장면 버전을 확정한다. 서버는 `story_id`, `step_number`, 장면 버전, `character_key`, 기준 이미지 버전, 선택된 행동을 함께 고정한다. 캐릭터 이름을 식별자로 사용하지 않는다.
2. 기존 장면 계약을 우선 사용해 행동, 소품, 대상, 배경, 인물 및 목표의 화면 위치, 이동 방향을 구조화한다. 불명확한 정보는 `unknown`으로 남기고 본문과 충돌하는 방향을 임의 확정하지 않는다.
3. 기존 장면 작업 API가 중복 요청을 합치고 작업 ID를 반환한다. 앱은 텍스트를 먼저 보여 주며 이미지와 영상 상태를 조회한다.
4. 백엔드 worker가 비공개 이미지 생성 서비스에 최소한의 장면 정보와 선택 캐릭터 기준 이미지를 보낸다. 이미지가 준비되면 콘텐츠 형식·크기 검사 후 GridFS에 저장하고 해당 장면 버전에 연결한다. 이미지 신원 평가는 별도 신뢰도이며 미검증임을 기록한다.
5. 영상 요청 시 저장된 동일 장면 이미지를 첫 프레임으로 원격 image-to-video 서비스에 전달한다. 프롬프트에 행동 및 목표 위치를 넣되, 지시가 준수된다고 가정하지 않는다.
6. 결과가 준비되면 영상 규격 검사 및 별도 행동·정체성 평가 후 같은 장면 버전에 연결한다. 검증 불충분은 표시하고 자동 품질 보장을 주장하지 않는다. 영상 실패 시 이미지와 텍스트는 유지하고 영상만 재시도한다.
7. 재접속 시 저장된 장면별 이미지·영상과 상태를 복원한다. 기존 동화의 결과물 저장이지, 차후 다른 동화에 쓰기 위한 에셋 축적이 아니다.

## 서비스 경계와 계약

- Flutter → FastAPI: 기존 장면별 POST/GET을 확장한다. 토큰 및 원격 Space 주소는 앱에 싣지 않는다. 앱·웹에서 도달 가능한 HTTPS 백엔드 주소가 필요하다.
- FastAPI → 원격 이미지: `reference_image`, `scene_description`, `action`, `seed`, 출력 크기, 생성 요청 ID. 반환값은 이미지와 모델·소요 시간·오류 코드. 사용자 계정 정보나 MongoDB 접속 정보는 전달하지 않는다.
- FastAPI → 원격 영상: `scene_image`, `motion_description`, `target_position`, `duration`, 생성 요청 ID. 반환값은 MP4와 모델·생성 시간·오류 코드. 결과 형식과 최소·최대 길이는 공급자 검증 후 확정한다.
- 네트워크 통신 및 접근 토큰은 백엔드에서만 처리한다. 외부 서비스에 실제 사용자 입력과 이미지가 전송되므로 운영 전 처리 목적, 보존·삭제 정책 및 필요한 동의를 확인한다.
- Space가 HTTPS 주소를 제공해도 백엔드가 로컬에서만 실행되면 다른 기기는 접근할 수 없다. 백엔드 및 데이터베이스 접속 정책과 사용자별 데이터 접근을 함께 검증한다.

## 작업 상태 초안

기존 `status`는 구버전 호환성을 위해 유지하고 다음 필드를 추가하는 방향을 검토한다. 이는 제안 계약이며 현재 구현된 필드가 아니다.

```json
{
  "job_id": "...",
  "status": "running",
  "scene_version": "...",
  "image": {"status": "completed", "url": "/api/media/images/...", "error_code": null},
  "video": {"status": "running", "url": null, "error_code": null},
  "identity_review": "not_verified"
}
```

각 미디어 상태: `not_requested`, `pending`, `running`, `completed`, `failed`. `status`와 `result.image_url`/`result.video_url`은 기존 클라이언트에 계속 제공한다. 모델 생성 종료를 즉시 장면에 반영하되, DB 갱신은 해당 작업의 lease/attempt 및 현재 장면 버전과 media_job_id를 조건으로 원자적으로 수행한다. 재시도 중 이전 worker가 늦게 돌아와 새 결과를 덮지 못해야 한다. 고아 파일은 별도 보존·정리 정책을 정한 후 처리한다.

## 실패와 제한

- 이미지 생성 실패: 오류와 재시도를 표시하고 동화 본문은 이용 가능하게 유지한다. 임시 화면에는 선택 캐릭터를 표시하되 생성 이미지인 것처럼 말하지 않는다.
- 영상 실패·할당량 소진·타임아웃: 이미지 유지, 영상 실패 상태 및 재시도 표시. 무한 재시도나 숨겨진 유료 전환을 금지한다.
- 원격 생성의 취소/타임아웃은 비용 또는 연산 취소를 보장하지 않는다. 공급자의 작업 ID·중복 방지 지원 여부를 조사한다.
- 시각 검사는 손·얼굴·행동·방향을 정확히 판정하는 보증 수단이 아니다. 자동 기준은 검증 데이터로 보정하기 전 보수적으로 운용한다.

## 검증과 단계

1. 비공개 시험 공간에서 승인된 `male_01`만 사용해 2~5초 image-to-video 실현 가능성, 성공 여부, 대기·처리 시간, GPU 할당량을 실제 측정한다. 영상 생성은 아직 시험하지 않았다.
2. 캐릭터 유지·목표 방향·동작 가독성을 사람이 여러 장면에서 확인하고 실패 사례를 기록한다. 모델·운영 환경 라이선스 및 이용 조건을 확인한다.
3. 공급자 어댑터와 독립 이미지/영상 상태를 테스트 대역으로 구현한다. 중복 요청, 타임아웃, image-only 성공, video-only 재시도, stale worker, 장면 이동, 재접속을 검증한다.
4. 사용자가 승인한 범위의 데이터로 FastAPI와 MongoDB 전체 흐름을 시험한다. 원격 서버 연결을 검증하기 전에는 실제 생성 완료로 표시하지 않는다.
5. 마지막으로 외부 HTTPS 배포 및 다른 기기에서의 인증·복구·오류 표시를 검증한다. 무료 할당량으로 가능한 동시 사용자 수와 서비스 범위를 실측한다.
