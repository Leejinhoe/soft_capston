# Antigravity 인계 검토 및 후속 조치

작성일: 2026-11-01. 목적: 선택 캐릭터를 유지하는 실시간 장면 이미지 및 영상 생성. Colab 상시 실행이나 동작 에셋 축적은 목표가 아니다.

## 확인된 사실

- `artifacts/character_lora_dataset.zip`을 읽기 전용으로 확인: PNG 144장, 서로 다른 character_key 16개, 각 9개 포즈, metadata.jsonl 항목 144개, 참조 이미지 누락 0건. 이미지와 캡션의 시각적 정확성, 원본의 권리와 전송 허가, 학습 적합도는 평가하지 않았다.
- `notebooks/fairytale_character_sdxl_lora_colab.ipynb`의 6번 셀은 정의되지 않은 `REPO_DIR`을 사용한다. 앞선 셀은 `PROJECT_DIR`을 정의한다. 또한 로컬 artifacts ZIP이 GitHub에 있다고 보장되지 않고, 4·8번 셀은 기존 5명용 설정과 샘플 프롬프트를 사용한다. 인계 노트북이 곧바로 16명 데이터셋을 학습·평가한다고 볼 수 없다.
- 해당 LoRA는 SDXL용이며 기존 시험용 FLUX.2-klein Space에 그대로 로드할 수 없다. LoRA 이미지 학습은 별도 문제인 image-to-video의 자연스러운 동작과 목표 방향을 해결하지 않는다.
- `media_queue.py`의 추가 응답에서 `partial` 상태의 영상이 대기 중으로 보이는 오류를 수정했다. 기존 필드는 유지한다. 상태 직렬화·작업 생명주기·재시도·이미지/영상 제공자 관련 회귀 테스트 총 105개 통과. 원격 생성 영상 실측은 아니다.

## 근거가 부족한 주장

- '16명 100% 동일', '소품 중복 원천 차단', '2~3초 보장', '쿼터 소진 없이 시간당 50~60장', 'Wan 실측 18~32초'에 대응하는 가중치·원격 실행 결과·재현 가능한 로그를 확인하지 못했다. 성능 목표나 가설이지 검증된 결과가 아니다.
- ZeroGPU 정책의 기준은 공식 문서다. 현재 공식 문서는 무료 계정 일일 할당량과 공유 큐를 설명한다. https://huggingface.co/docs/hub/en/spaces-zerogpu
- SDXL LoRA 학습은 16개 캐릭터 이미지를 새 학습 환경으로 전송하며, 기존 male_01 비공개 Space 테스트 허가와 범위가 다르다. 추가 허가 및 원본 권리 확인 전 업로드·학습하지 않는다.

## 남은 일

1. Antigravity에 실측 로그 출처, 노트북 및 데이터 경로 결함, SDXL/FLUX 호환성 문제를 공유하고 최신 작업 여부를 확인한다. 동시 편집하지 않는다.
2. 이미지 정체성 향상용 LoRA가 별도 연구로 타당한지 비교하되, 실제 목표인 원격 image-to-video 서비스 후보 검증을 대체하지 않는다.
3. 영상 원격 제공자 사용 조건과 범위를 확정하고, 승인된 입력으로 짧은 영상의 성공·지연·품질을 실측한 후 앱 미디어 작업과 결합한다.
4. 백엔드 응답에서 image/video 상태를 직렬화하는 것과 이미지가 영상보다 먼저 실제 저장·표시되는 것은 다르다. 후자는 아직 구현·검증이 필요하다.
